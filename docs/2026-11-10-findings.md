基线是当时的分支头：`main` `2645d9e51a12bf504da63e221b67a86a6517f109`，`slim` `e9569d5ece06649d6e0234c12e236f99fae497db`。上游审查水位仍以 [upstream-sync.md](./upstream-sync.md) 为准，本页不改那张表。

查重时本仓没有未结议题。GitHub 议题工具当时不可用，下面各项没有新建议题，也没有改用命令行补开。

交接来自用户 M2 上的报告。本轮只核对源码是否仍支持那些结论，没有重跑他们的 macOS fixture，也没有读取真实会话。

## 源码仍支持的项

| 编号 | 分支 | 本轮核对 |
| --- | --- | --- |
| MSA01 | 两分支 | `proxy.rs` 把 `https` 映射成 HTTP，并用裸 TCP 发送 `CONNECT` 和 Basic。 |
| MSA02 | main 经 slim 再回 main | `slim` 没有 MCP 字段；`main` 的 `mcp_access` 默认 `true`。保存会丢掉显式的 `false`。修复不能把 MCP 加回 `slim`。 |
| MSA03 | 两分支，函数相同 | `download_impl` 在提前 EOF 时，`done` 小于 `total` 仍 `Ok(true)` 并标成功。 |
| MSA04 | 两分支，函数相同 | ZMODEM `File::create` 会截断同名文件。尚未在隔离目录做覆盖试验。 |
| MSA05 | 仅 slim | 更新检查请求 `releases/latest`。`parse_version` 丢掉 `-slim.N`。 |
| MSA06 | 仅 main | `cli exec` 打印结果后总是 `Ok(())`。不要为此改 MCP 返回字段。 |
| MSA07 | 两分支 | 过期快照拒绝写入是对的。界面多处 `let _ = save()`，失败看不见。 |
| MSA08 | 两分支 | `Session.proxy` 是普通字符串，代理口令会进 `sessions.json`。这不是导出文件的口令保护。 |

## macOS CPU

没有在 macOS 上测量。云上 Linux 的 CPU 不能当作 Mac 的结果。壁纸没有被当成原因：壁纸在选择或启动时设置，没有找到它自己的定时器。

源码里和持续唤醒有关、但尚未量化的路径：

- 每个窗口有 1 秒一次的本机采样定时器。隐藏时回调直接返回，后台每 5 次才采样，前台每秒采样。定时器在隐藏时仍会响。采样跑在界面线程。
- 侧栏展开且不是专注模式时会开远端资源监控，折叠或专注时关掉。
- 终端重绘最短间隔 33 毫秒，只在有输出要求绘制时发生。
- 传输按钮的呼吸动画是无限循环，只在有传输时可见。没有传输时该层隐藏。隐藏之后动画时钟是否还在走，没有测过。
- 光标闪烁跟窗口是否聚焦有关。

最小测量：用正式 v0.7.13 mac 包（报告中的 sha256 `15beebaade67335f804fcd064cce393014ca193cab5eed85381bed447211ddf8`）和空数据目录，壁纸关闭，不要用真实会话。各记 60 秒：空闲窗口、连上但不输出、持续输出、隐藏窗口、断开会话、折叠侧栏。数字门槛等第一次 Mac 采样再定。
